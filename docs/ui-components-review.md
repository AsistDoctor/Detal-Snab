# Ревью UI-компонентов «Деталь Снаб»

Документ: инвентаризация всех UI-компонентов сайта по макетам Figma (файл Detal_snab, 16+ экранов: 1440 / 768 / iPhone SE) + ревью состояний каждого компонента.
Дата: 2026-11-17. Составил: ЗКод (по макетам + живой осмотр файла в Figma).
Статус дизайна: дизайнер рисовал «счастливый путь» (happy path) без интерактивных состояний — это зафиксировано честно, всё додуманное помечено ⚙️.

## 2. Атомы (базовые компоненты)

### 2.1. Кнопка — `VButton`
**Где:** «Войти», «Зарегистрироваться», «Сохранить изменения», «Применить», «Оформить заказ», «Вернуться к заказам», «Очистить», «Оплатой картой»/«Перевод на карту», «Скачать», «Приложить чек», «Оплатить», «Отмена».

**Варианты, найденные в макетах:**
| Вариант | Вид | Пример |
|---|---|---|
| Primary | синяя заливка, белый текст | «Войти», «Оформить заказ», «Сохранить изменения» |
| Disabled | серая `#D9D9D9`-заливка, белый текст | «Зарегистрироваться» (пока чекбоксы не нажаты), «Оплатить», «Отмена» |
| Secondary (gray) | светло-серая заливка, тёмный текст | «Очистить», «Оплатой картой», «Перевод на карту», «Приложить чек» |
| Sizes | от узкой (Войти ~150px) до full-width («Сохранить изменения», «Вернуться к заказам») | — |

**Ревью:** есть 3 из 6 нужных состояний (default / disabled / secondary-вариант). **Нет:** hover, active (нажатие), focus-visible (с клавиатуры), loading (спиннер при отправке формы), фокус-контур.
**⚙️ Решено мной:** hover = затемнение до `#004A8C`, active = сдвиг на 1px, loading = спиннер внутри, focus = контур 2px. Размеры унифицированы: 36px (таблицы) / 44px (формы).

### 2.2. Поле ввода — `VInput`
**Где:** формы входа/регистрации/профиля (лейбл слева, серая заливка `#EFEFEF`, без рамки), поиск в шапке (белый, рамка, иконка 🔍), поиск по счетам (placeholder «Поиск»), фильтры поиска (placeholder).

**Ревью:** в макетах ДВА несовместимых стиля (формы vs поиск) — это норм, фиксирую как два пропса `variant: form | search`. Обязательность помечена звёздочкой в лейбле (`Email*`) — норм.
**Нет состояний:** focus, error (текст ошибки + красная рамка), success, disabled, readonly, placeholder в формальных полях.
**⚙️ Решено:** focus = синяя рамка + мягкая тень; error = красная рамка + подпись под полем; в форме placeholder добавляю только там, где он помогает (телефон «+7 (___) ___-__-__»).
**Фича:** в формах лейбл стоит СЛЕВА от поля (FormRow), в поиске — placeholder внутри. На мобилке лейбл-слева не влезает → переход на лейбл сверху (в SE-макетах форм нет, решение моё).

### 2.3. Чекбокс — `VCheckbox`
**Где:** «Запомнить меня», «Согласен на обработку…» (вход), выбор типа регистрации (2 шт.), 2 согласия при регистрации, «Выбрать все» (корзина), чекбоксы строк корзины, «Сохранить настройки доставки».

**Ревью — самый бардак компонент:** найдены ТРИ разных отрисовки отмеченного состояния: (1) серый квадрат-галочка (нативная, «Физическое лицо»), (2) синий квадрат с белой галкой (согласие услуг), (3) серый квадрат с галкой («Выбрать все»). Плюс выбор типа регистрации сделан чекбоксами, хотя это взаимоисключающий выбор = должны быть radio-кнопки.
**⚙️ Решено:** один стиль — синий `#00579F` с белой галкой для checked, серый контур для unchecked; тип регистрации переделываю на radio (визуально похожи, логика верная). Disabled-стейта нет — добавляю.

### 2.4. Выпадающий список — `VSelect`
**Где:** «Вид доставки» (Самовывоз), «Привязать автомобиль» (Не выбран), «Выберите статус» (счета).
**Ревью:** нарисован только closed-стейт (нативный вид с ▼). Опции, hover, поиск внутри списка — не нарисованы.
**⚙️ Решено:** нативный `<select>` со стилизацией (дёшево и надёжно); кастомный дропдаун — только если понадобится поиск/чекбоксы в списке.

### 2.5. Дата — `VDateInput`
**Где:** фильтр счетов «с … по …» с иконкой календаря.
**Ревью:** нарисованы только пустые поля с иконкой. Сам календарь-поповер не нарисован.
**⚙️ Решено:** нативный `<input type="date">` со стилизацией под поле.

### 2.6. Счётчик количества — `VQuantity`
**Где:** корзина, колонка «Кол-во»: квадратные кнопки − / + (синий контур) и число между ними.
**Ревью:** нет состояний min (шт. 1 — кнопка − должна гаснуть), max (нет на складе), ввода с клавиатуры.
**⚙️ Решено:** disabled на границах, прямой ввод числа разрешён.

### 2.7. Ссылка — `VLink`
**Где:** «Восстановить пароль», «Зарегистрироваться» (синие подчёркнутые), «соглашения» (внутри чекбокса), «Редактировать» (в профиле ЛК), «все» (активный период), «История» (баланс), «Удалить выбранные» (чёрная).
**Ревью:** два стиля (синяя подчёркнутая / чёрная текстовая) + активное состояние («все» синий). Hover не нарисован ⚙️ = подчёркивание.

### 2.8. Бейдж статуса — `VStatus`
**Где:** счета «⚠ Ждет оплаты» (красная иконка !); в балансе ЛК статусы текстом («Не обработан»).
**Ревью:** нарисован только один статус из минимум четырёх (ожидает оплаты / оплачен / отменён / в работе).
**⚙️ Решено:** система цветов: красный = ждёт оплаты, зелёный = оплачен/выполнен, жёлтый = в работе, серый = отменён.

### 2.9. Иконки
**Где:** пин, телефон, юзер (топлайн); корзина (шапка, карточки); поиск; календарь; бургер/крестик; галочки; ✕ удаления; ‹ › стрелки; ⌄ каретка; ! статуса; ⬇ скачать; 📎-аналог «приложить чек».
**Ревью:** в файле нарисованы векторами без экспорта; часть (корзина шапки, галка согласия) — растровые вставки.
**⚙️ Решено:** весь набор перерисован monoline SVG 1.7px `currentColor` — заодно легли на сетку 16/18px.

### 2.10. Разметка-мелочёвка
**Хлебные крошки** (`Главная / Новым клиентам / Доставка`): последняя — серая жирная, предыдущие — обычные. Косяк макета: на «Контактах» крошка называется «Адреса магазинов», а не «Контакты» — записал в вопросы.
**Заголовок секции** (`БРЕНДЫ` + кнопка «ВСЕ БРЕНДЫ»): uppercase PT Sans Bold 16 + outline-кнопка справа.
**Бейдж акции** («−30%»): красный, на hero и… в карточках товаров макета бейджей нет (в демке были «Хит продаж» — вопрос: нужны ли?).
**Итоговая строка таблицы** («Итого товаров: 3 на сумму 6448.00 ₽»): справа, сумма болдом.

## 3. Молекулы (составные блоки)

### 3.1. `FormRow` — лейбл слева + поле
Стандарт форм входа/регистрации/профиля. ⚙️ на <768px лейбл уезжает наверх.

### 3.2. `FormSection` — карточка-секция формы
Белая карточка с рамкой и заголовком («Регистрационные данные», «Ваши контактные данные», «Адрес доставки», «Данные о компании», «Юридический адрес»). Состав секций фиксирован макетами — переиспользую как есть.

### 3.3. `ConsentLine` — чекбокс + текст с ссылками
«Согласен на обработку персональных данных и принимаю условия соглашения» (соглашения — ссылка). При регистрации согласий два, одно предотмечено. ⚙️ логика: кнопка регистрации disabled, пока оба не активны.

### 3.4. `ProductCard` — карточка товара
Фото (4:3, воздух), «Артикул: 153789» серым, название болдом (TT Commons→PT Sans), цена болдом + старая цена зачёркнутая, кнопка-корзина (контур синий).
**В макетах:** 3 из 4 карточек на главной БЕЗ фото (заглушки). Бейджей нет. Hover не нарисован. Стейт «товар уже в корзине» не нарисован. Мобильная карточка — та же, 2 в ряд.
**⚙️ Решено:** hover = тень + подъём; клик по корзине = тост «Добавлено»; бейджи оставил (демо-фича, легко выключить).

### 3.5. `CategoryTile` — плитка категории
Серая `#EFEFEF`, uppercase bold; активная/featured — синяя с белым текстом («Аккумуляторы»). На SE — full-width строки списком. Состояние hover = синий (⚙️ по аналогии с featured).

### 3.6. `BrandCard` — логотип бренда
Белая карточка, логотип по центру (Komatsu, Caterpillar, Cummins, JCB, ITR, G.A. Ricambi, OFM, CGR). 4 в ряд на всех экранах, на SE — компакт.

### 3.7. `NewsCard`
Серое фото-место + дата (04.01.26) + заголовок («Новое поступление») + текст + «Подробнее». На десктопе в макете текстов нет (голые серые блоки) — взял формат с SE-макета. ⚙️

### 3.8. `OfferCard` — поисковая оффер-карточка
«МИНИМАЛЬНАЯ ЦЕНА / В НАЛИЧИИ / БЫСТРАЯ ДОСТАВКА»: фото-заглушка, «НАИМЕНОВАНИЕ ТОВАРА……①», срок/наличие, цена 25 888.00 ₽, синяя кнопка-корзина. Бейдж «В наличии 14 шт.» синий. **Три карточки над таблицами поиска.**

### 3.9. `CartRow` — строка корзины (табличная!)
Колонки: чекбокс | Артикул+бренд | Наименование | Срок (1-2дн.) | Склад (AES) | Цена | Кол-во | Вес | Сумма | ✕.
**Ревью:** это НЕ карточная корзина из демки — таблица в стиле страницы поиска (B2B-стиль). Веса товара нет в данных демо ⚙️ (добавил поле). На мобилке (SE) строки оседают в стек — макет есть, беру его.

### 3.10. `QuickPeriods` — быстрые периоды
«Счета за: 3 дня / неделю / месяц / год / все», активный «все» синим. ⚙️ радиологика на текстовых ссылках.

### 3.11. `TableActions` — кнопки в строке таблицы
«Скачать ▼» (серая с дропдауном — само меню НЕ нарисовано ⚙️ сделаю: PDF/печать), «⬇ Приложить чек» (белая с иконкой), «Оплатить» (серая/disabled).

### 3.12. `UserInfoRow` — пара «лейбл: значение»
Профиль ЛК («Имя — Иванов Иван»), баланс («Состояние счета — 0.00₽»), менеджер («Имя — Петр Петрович»). Лейбл болдом слева, значение справа.

### 3.13. `ChoiceButton` — выбор оплаты кнопками
«Оплатой картой» / «Перевод на карту» — большие серые кнопки-опции на «Заказе оформлен». Состояние selected не нарисовано ⚙️ = синяя рамка/заливка.

## 4. Организмы (секции и страницы)

### 4.1. `SiteHeader` — шапка ✅ сделана
Топлайн: пин+город, телефон, меню (О компании, Новым клиентам⌄, Для поставщиков, Новости, Контакты), Вход с иконкой. Основная строка: лого, синий «Каталог» с сеткой-иконкой, поиск, корзина-пилюля с бейджем количества.
**Ревью:** каретка «Новым клиентам ⌄» намекает на дропдаун-меню — **не нарисован** ⚙️ (сделаю простое меню-ссылки). Бургер на SE нарисован, содержимое меню не нарисовано ⚙️ (панель со ссылками топлайна). Активный пункт меню не показан ⚙️ = синий.

### 4.2. `SiteFooter` ⚙️ — в макете ОТСУТСТВУЕТ
Проверено поиском по слоям: фрейма/группы футера нет, главная заканчивается без него. Собран мной: синяя полоса + лого + 3 колонки + нижняя строка. **Вопрос дизайнеру: нарисовать или ок так?**

### 4.3. `Hero` — главная витрина ✅ сделана
Десктоп: плитка «Тормозные колодки −30%» + «ТОП ПРОДАЖ 2026» (клин) + «Моторное масло» (синяя волна) + «Шины и диски». ≤900px: слайдер со стрелками и точками (по 768-макету).
**Ревью:** для слайдера нарисованы точки (1 активная) и стрелки; контент остальных слайдов на мобиле не показан ⚙️ = те же 4 плитки.

### 4.4. `BrandsSection` / `CategoriesSection` / `ProductsCarousel` ✅ сделаны
Популярные товары = карусель со стрелками ‹ › (левая серая = disabled — единственный нарисованный disabled-стейт стрелок ⚙️ применяю логику границ).

### 4.5. `SearchPage` — подбор по артикулу (стр. «поиск») — БУДУЩИЙ РЕФАКТОРИНГ
Заголовок-«Наименование товара 00 00 00 000» + карточка детали (фото, Артикул/Производитель RENAULT/Наименование, «О производителе», кнопка «Найти в каталоге», «Все параметры ⌄») + панель фильтров (Цена с ползунком, Поставщик, Мин. срок, В наличии от, Производители с поиском, Тип предложения) + 3 OfferCard + таблицы «Есть в магазине / Запрашиваемый код / Оригинальные аналоги» (Деталь/Срок/Доступно/Цена + корзина).
**Ревью:** ползунок цены (red line!) нарисован статично — двойное поле ввода есть, сам слайдер-компонент ⚙️ нативный range. Итоговая «Найдено N» отсутствует. Empty-state («ничего не найдено») отсутствует ⚙️. Пагинация отсутствует ⚙️ (кнопка «Показать ещё»).
**Состояния поиска -1/-2** (переключение вкладок/городов) — в файле есть, до конца не разобраны — отдельная сессия.

### 4.6. `CartPage` — корзина (переписать из демки!)
Чекбокс «Выбрать все» + «Удалить выбранные» → таблица CartRow → итог → «Оформить заказ». Под таблицей — карусель «ПОПУЛЯРНЫЕ ТОВАРЫ».
**Ревью:** пустая корзина не нарисована ⚙️. Подтверждение удаления не нарисовано ⚙️ (модалка или тост).

### 4.7. `CheckoutPage` — оформление (переписать!)
Крошки «Личный кабинет / Корзина / Оформление заказа». Карточка «Вид доставки»: select «Самовывоз», checkbox «Сохранить настройки доставки», «Комментарии к заказу» (textarea). Справа «Ваша корзина»: Товары 3 шт., Сумма заказа, **«Привязать автомобиль» select («Не выбран»)**, «Итог к оплате», кнопки «Оформить заказ» + «Отмена» (серая).
**Ревью:** это checkout для ЗАЛОГИНЕННОГО юзера — полей адреса/ФИО нет (данные из профиля). Гостевого чекаута в макетах нет ⚙️ (решение: без логина заказ идёт через упрощённую форму). «Привязать автомобиль» — B2B-фиша, списка авто нет ⚙️ (демо: селект с 2-3 заглушками). Вариант «Доставка ТК» контента не показан (что открывается при выборе) ⚙️ = поля города/адреса/ПВЗ.

### 4.8. `SuccessPage` — заказ оформлен
Крошки, H1 «Заказ оформлен!», карточка «Заказ №4444 от 6.05.20024» (⚠️ опечатка дизайнера в дате) + Способ получения/Сумма; карточка «Выберите способ оплаты» (ChoiceButton ×2); full-width «Вернуться к заказам».
**Ревью:** для юрлица отдельный вариант макета («Заказ оформлен_юрлицо») — отличается способами оплаты (счёт). Номер заказа/дата — из системы (демо: генерим).

### 4.9. `AuthPages` — вход и регистрация
Вход: H1 «Вход», карточка (Телефон или Email*, Пароль*, «Запомнить меня», «Войти», ссылки «Восстановить пароль»/«Зарегистрироваться», согласие). Вход по телефону ИЛИ email — не только email, как в демке ⚙️ поправить.
Регистрация: тип (Юр/Физ чекбоксами → radio), секции (Рег. данные / Контактные / Адрес доставки; для юр. + «Данные о компании» (ИНН, КПП, Банк, БИК, Счет, Корр.счет, ОГРН, ОКПО) + «Юридический адрес»), 2 согласия, disabled-кнопка.
**Ревью:** табов «Вход/Регистрация» в макете нет — это две отдельные страницы, связанные ссылками. Восстановление пароля не нарисовано ⚙️ (заглушка-форма). Кнопки-переключатели типа при клике: контент секций меняется — нарисованы оба состояния ✅.

### 4.10. `AccountDashboard` — личный кабинет (ПЕРЕДЕЛАТЬ из демки!)
Совсем другой, чем сайдбар в демке: H1 + «000-000-00» в рамке + красное «Ваш код для получения заказа»; 3 карточки: Профиль (с «Редактировать» и «Уровень цен: Розница», «Дисконтная карта: Введите номер карты»), Баланс (4 строки + «История»), Ваш менеджер (персональный менеджер с контактами!); плитки-разделы: Заказы, Корзина, Счета, Накладные, Отправки.
**Ревью:** плитки разделов = ссылки на подстраницы (Заказы/Накладные/Отправки не нарисованы вообще ⚙️). «Уровень цен: Розница» намекает на B2B-цены (Опт1/Опт2) — без бэка рисуем константой. Код заказа — генерим демо-числом. «Дисконтная карта» — поле ввода без логики.
«Редактирование личных данных» = та же форма, что регистрация без типа и согласий + «Сохранить изменения». ✅ берётся напрямую.

### 4.11. `InvoicesPage` — счета

### 4.12. `InfoPages` — Доставка / Оплата / Контакты / Как сделать заказ / О компании
